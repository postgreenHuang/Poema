# Poema

一座会与你谈诗的私人诗库。当前交付为可运行的桌面原型，产品方向见 [完整方案](product-blueprint.md)。

## 已能使用

- **今日偶遇**：从 5000 余篇本地中英文作品随机换诗，中文优先探索非名篇选本，并分散文体与近期读过的作者；点击文句可点亮它。诗笺、共读与“再遇一首”固定在阅读页顶部。
- **寻诗**：按题名、作者、原句、语言、文体和意象搜索，也能理解“写雨但不悲伤的短诗”一类常见需求。可单独筛选诗、词、曲、《诗经》、楚辞和古文。
- **诗路**：从当前诗按意象、心绪、形式或反向情绪继续阅读，显示具体关联理由，并可回到上一首。
- **AI 共读**：每首诗单独保留对话；选句后提问会把该句加入上下文。可配置兼容 `/chat/completions` 的服务与模型。没有模型时，其余阅读功能照常可用。
- **诗笺**：收藏、私人笔记、最近阅读与对话保存在本机，可导出 JSON。
- **阅读主题**：在“偏好与 AI”中切换松烟、夜读、旧纸，或分别微调页面、侧栏、卡片、标题、诗句、次要文字、强调色和分隔线。配色即时生效，仅保存在本机。
- **来源**：每篇作品都有来源链接和许可说明。英文数据来自 PoetryDB，按 CC BY 4.0 署名；中文扩充语料来自 chinese-poetry，并附其 [MIT 许可](public/CHINESE-POETRY-LICENSE.txt)。

## 启动

需要 Node.js 22+。桌面版还需要 Rust stable、Windows C++ Build Tools 和 WebView2。

```powershell
npm install
npm run dev
```

浏览器预览地址为 `http://127.0.0.1:1421`。桌面开发模式：

```powershell
npm run tauri dev
```

构建 Windows 调试可执行文件：

```powershell
npm run tauri build -- --debug --no-bundle
```

输出路径为 `src-tauri/target/debug/poema.exe`。本版未制作安装器或签名。

## AI 与隐私

在“偏好与 AI”中填写服务地址、模型 ID 和 API Key。桌面版密钥存于系统凭据库；浏览器预览版密钥仅存在当前标签页的会话存储。Poema 会向所选模型发送当前诗、选中的诗句以及本首诗最近 12 条对话，不发送整个诗笺。浏览器预览是否能直连模型服务取决于其 CORS 设置；桌面版由 Rust 发起请求。

当前对话回复尚未进行模型供应商的真实密钥联调，使用时需要自行配置服务。AI 解释会要求区分文本、事实和解读，但仍应核对涉及生平、背景和版本的陈述。

## 数据边界

原有 422 首样本之外，新增 4848 篇发现语料：唐诗 1500、宋诗 1368、宋词 1200、元散曲 350、《诗经》240、楚辞 30、《古文观止》短篇 100、《幽梦影》短章 60。扩充语料来自 chinese-poetry@2.0.1 的跨分片抽样，按固定哈希、作者上限、篇幅和缺字规则筛选；元曲仅保留可独立阅读的散曲，排除戏剧片段。样本和逐分片 SHA-256 记录在 `src/data/discovery.json` 与 `src/data/discovery-report.json`。生成脚本为 `scripts/build-discovery.mjs`；重建时先将该 npm 包中脚本列出的分片解压到忽略提交的 `.source-corpus/package/dist/`，再运行 `npm run import:discovery`。

开源原始语料远比目前的离线入选库大；本版仍是经过基本格式筛选的发现库，而非全量总库。全量接入宜迁移到 SQLite 索引并建立逐篇校勘、去重和权利审查流程，避免把海量未经核验的文本直接打包进阅读界面。

中文文本的自动简化字转写尚未逐篇校勘，来源链接和权利说明随每篇作品保存。按心绪筛选时，扩充语料只纳入含明确情绪词面的作品；这是粗略线索而非人工鉴赏结论。

本版尚未接入 Wikisource/Wikidata 增量同步、现代诗授权库、译本与朗读录音，也未实现方案中设想的 SQLite 全文索引。检索目前在本地已打包的作品中完成。

本机收藏与对话目前保存在 WebView/浏览器的 `localStorage` 中。JSON 导出可作为备份；进一步扩大语料或做跨设备同步前应迁移到 SQLite 和版本化的来源/权利模型。
